## 1. Method

The plan was to drive the application with the computer-use tools, as a person
would. Those tools were not available in the session. So a script started the real
application (`Cognia` from `src/app/application.py`, the real models, the real 3D
page) and acted on the real widgets as a person does: it clicked buttons, typed
into the fields, pressed Enter, and waited for each result. It timed each step and
saved a picture of the screen. The person the script plays is a new user who has
never seen Cognia and does not read any document.

Each task below states what the user wants, what happened, and the time it took.

## 4. Defects found and fixed during the test

These were faults in the new work, against the approved behaviour. Each was fixed
before this report and the test suite ran again.

1. **A crash when a tool ran.** The gesture "think" was called from the model
   thread, and Qt ended the process. The call now goes through a slot on the
   window's thread.
2. **The tips of the first steps were cut or pushed to the right.** The lines now
   wrap inside their card.
3. **"Saved" vanished at once in Speaking up.** The settings were shown after the
   line that said saved, which cleared it. The order is now the other way.
4. **"I was paused for 0 minutes."** A pause shorter than a minute now says "less
   than a minute".

## 5. Weak points, most serious first

Not fixed: each needs a decision of the author.

1. **The talk key does not work on this machine.** Another application already
   holds `Ctrl+Alt+Space` (Windows error 1409). Cognia says so in the conversation
   and the talk key stays off until the user chooses another in Settings › Voice.
   `Ctrl+Alt+K` and `Ctrl+Shift+Space` were free. A new user meets an error before
   the first word. Options: try a short list of defaults at first start and keep
   the first free one, or ask for the key in the first steps.
2. **The companion costs far more memory than NFR-06 allows, and hiding it frees
   little.** Hiding ends the render process, but the browser and GPU processes of
   Chromium stay, about 480 MB. Options: end the whole web engine when the
   companion hides (a slower show), accept a new figure in the specification, or
   frames rendered in advance (D-08, option D).
3. **The first words take 12 s.** The interpretation runs before the reply, and the
   model loads at the first message. The indicator shows, so NFR-05 holds by its
   second clause, but the wait is long for a first message. Options: load the
   model while the user picks a character; run the interpretation after the reply
   starts.
4. **The reply quotes the stored line in quotation marks** ("I'll remember "Has a
   cat called Miso""). It sounds like a form, not a friend. This is the
   show-back instruction (D-47) on the published model; the tuned model of D-80 may
   fix it.
5. **The feeling did not move after the first message.** The message was read as
   small talk, so "Why Yuna feels this way" says "Nothing in the last 7 days" while
   the user just introduced themselves. Correct by the rules, but a user may expect
   a small reaction.
6. **The Python process holds about 1.5 GB.** Most of it is the 32-bit Kokoro model
   and onnxruntime, loaded at the first spoken reply and kept. Unloading the voice
   after some minutes of silence would return it.
7. **The title of a conversation is the whole first message, cut.** "Hi! I'm Linh,
   and I have a cat called M…" is a poor name in the picker.

## 6. What this test did not cover

- **The messages Yuna starts on her own.** A break suggestion needs 75 to 110
  minutes at the desk, a remark 90 to 180 minutes of quiet, and dozing 30 minutes
  away. The unit tests of `domain/initiative`, `domain/speech` and the core
  handlers cover these paths; nobody saw a bubble on the desktop in this test.
- **A real microphone and a person's ears.** The speech engine heard audio that
  Kokoro made, and the voice played, but no person listened to it or spoke.
- **The talk key**, because it could not be registered (weak point 1).
- **Start with Windows**, which writes to the registry of the user; it was not
  switched on.
- **The look of each gesture with a person watching.** Pictures of each gesture
  were taken on the screen during the work and match the intended motion; a person
  should still judge whether they look natural.
- **Outbound connections of Chromium** (NFR-01). The page refuses every URL that is
  not a local file; nobody captured the network in this test.
